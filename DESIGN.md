# Northwind UI: design rules

How to build screens with `@northwind/ui`. For people and AI agents.
Read this before building a screen. Component props and examples are in Storybook (also through the Storybook MCP).

## The short version

- Build only from `@northwind/ui`. Never import `@mui/*` in product code. Lint blocks it.
- Layout with `Stack`, text with `Text`. No inline styles, `sx`, `className` or raw colours. Lint blocks those too.
- If the system doesn't have what you need, **build it from what exists and say what was missing in your PR**. Don't work around the system. A reported gap is useful; a workaround hides it.

## Components

| Component | Use it for | Don't |
|---|---|---|
| `Button` | Actions. `primary` for the main action (one per area), `secondary` beside it, `ghost` for low-emphasis actions in toolbars, lists and card footers, `danger` for destructive actions. | Use `danger` without a confirmation step. Use more than one `primary` in a card or dialog. |
| `TextField` | Single-line input. Always give a `label`. Pair `error` with a `helperText` that says how to fix it. | Use `placeholder` as the label. |
| `StatusLabel` | The state of a record, often in a table row or a card's `action`. | Make it clickable. Use it for counts or categories. |
| `Alert` | A message about the page or a task. `info`, `success`, `warning`, `error`. | Stack more than two on one screen. Use `error` for something that only needs attention. |
| `Card` | Grouping related content: a site, a report, a form. Title, optional subtitle, optional `action` at the top right, `footer` for buttons. | Nest cards inside cards. |
| `Stack` | All layout: rows, columns, gaps, alignment. | Reach for divs and CSS. |
| `Text` | All text. `body2` is the default for dense screens. | Pick a variant for its size alone; headings should follow the page structure (use `as`). |
| `ColorSchemeSwitch` | Letting users choose light, dark or system. Once per app, usually in the header. | |

## Writing

- **Sentence case** everywhere: "Save changes", not "Save Changes" or "SAVE CHANGES".
- **Buttons start with a verb**: "Export CSV", "Renew permit". Not "OK" or "Yes".
- **Status labels describe themselves**: "Overdue", "Pending review", "Due in 2 days". Not "Red" or "Status 3".
- **Errors say what's wrong and how to fix it**: "Enter a full email address, like name@example.com."
- **Dates and times**: "Today, 08:12", "Yesterday, 17:40", "Mon 26 Oct", "26 Oct 2025" for another year. 24-hour clock.
- **Numbers**: commas for thousands (12,400), and a space before units (4.2 t, 18 °C).

## Layout

- Spacing steps (1 = 8px): `1` between related controls (buttons in a row), `2` inside cards and forms, `3` between sections, `4` around the page.
- Put the primary action last (rightmost) in a row of buttons.
- Use `direction="row" justify="between"` for a heading with an action or status on the right.

## Colour

- Colour comes from roles, set by the theme. Choose roles through props, never by value.
- Status colours (`error`, `warning`, `success`, `info`) are for reporting status only. Not for decoration or brand.
- Never use colour alone to carry meaning: pair it with a label or an icon.
- Every screen must work in light and dark. Check both.

## Not in the system yet

Tables, icons, navigation, dialogs, select menus, tabs, date pickers. If a screen needs one, say so in the PR.
MUI has all of these; they will be wrapped when there is a real use for them.
